> 版本：v1.0

> 状态：Step 6 主 PRD
> 关联文档：`docs/brd.md`（业务需求）、`memory-bank/schema.md`（数据库）、`memory-bank/design-document.md`（设计决策）、`memory-bank/architecture.md`（架构）

## 1. 产品概述

### 1.1 背景与目标

京东充电桩安装业务中，各服务商费用记录方式各异、口径不一：

- 城南安装 —— 领退料方式记录
- 远程机电 —— 分段工程方式记录
- 安家安装 —— Excel 方式记录

这些记录方式与京东收费拆分标准不一致，业务人员需**人工跨表核对**，效率低、且核对过程与结果**无留存**。

**目标**：服务商在线提交费用明细 → 系统自动映射京东标准库核对 → 生成可追溯结算账单，将单笔核对从 **30 分钟降至 5 分钟**，且**全过程可追溯、可留存**。

### 1.2 用户角色

| 角色 | 是否有账号 | 职责 |
| --- | --- | --- |
| admin（管理员） | 有 | 维护标准费用库 |
| operator（运营） | 有 | 发起核对、核对费用明细、处理结算 |
| provider（服务商） | 无 | 通过工单链接提交费用明细 |

> 使用方为京东业务侧，约 20 人，仅限内网使用。

### 1.3 核心价值主张

1. **提效**：自动映射标准库，人工只需处理异常项，核对耗时 30 分钟 → 5 分钟。
2. **统一口径**：全局固定的京东标准费用库，所有工单共用同一套核对基准。
3. **可追溯**：服务商原始提交、系统核对结果、人工处理记录、结算账单全链路留存。
4. **零门槛**：服务商免账号，凭 token 链接即可提交，降低接入成本。

## 3. 功能模块说明

> 每个模块含：功能描述、用户故事、验收标准。

### F01 工单管理

**功能描述**

operator 通过「+ 发起核对」录入京东工单信息（京东工单号、服务商名称、项目地址、安装完成日期），创建核对任务单，系统自动生成服务商提交链接 token。

**用户故事**

- 作为 operator，我希望通过「发起核对」录入京东工单信息，以便为服务商生成提交链接。
- 作为 operator，我希望系统自动生成唯一的提交 token，以便服务商免登录提交。
- 作为 operator，我希望必填项校验清晰，以便避免创建无效工单。

**验收标准**

- 「发起核对」弹窗含 4 字段：京东工单号、服务商名称（下拉）、项目地址、安装完成日期（默认今天）。
- 京东工单号 / 项目地址 / 安装完成日期为必填，缺失时给出提示。
- 工单创建后状态为 `pending_submit`，在列表最顶部显示。
- 生成唯一 `submit_token`，服务商链接为 `/submit/{token}`。

### F02 工单列表与待办

**功能描述**

列表展示全部工单，支持状态 Tab 筛选、工单号/服务商模糊搜索、分页；顶部待办卡汇总「待核对 / 争议中 / 超 3 天未提交」，可点击快速筛选。

**用户故事**

- 作为 operator，我希望按状态筛选和搜索工单，以便快速定位目标工单。
- 作为 operator，我希望看到待办汇总数字，以便优先处理紧急工单。
- 作为 operator，我希望列表按状态提供对应操作，以便一步进入后续流程。

**验收标准**

- 6 个状态 Tab（全部/待提交/待核对/已核对/已结算/争议中）+ 搜索 + 分页（20 条/页）。
- 待办卡数字与列表实时一致；点击待办卡按对应状态筛选。
- 状态以「圆点 + 文字」标签展示（无背景色块）。
- 行操作按状态展示：待提交→复制提交链接；待核对/争议中→进入核对；已核对/已结算→查看账单。

### F03 服务商费用提交（token 免登录）

**功能描述**

服务商通过工单链接 `/submit/{token}` 免登录进入提交页，按标准费用项分区填写数量/米数（基础安装仅需确认勾选；桥架/电缆/断路器填数；其他增项填名称 + 金额），系统实时计算总额，提交后工单进入待核对。

**用户故事**

- 作为服务商，我希望通过链接免登录提交费用明细，以便快速完成申报。
- 作为服务商，我希望实时看到合计金额，以便核对无误后提交。
- 作为服务商，我希望单价由系统预设，以便只填数量、减少录入错误。

**验收标准**

- `/submit/{token}` 免登录可访问。
- token 不存在或已失效时，页面显示「链接无效或已过期」错误提示。
- submit_token 一次性有效：服务商提交成功后，再次访问同一链接展示只读状态（显示「已提交，等待核对」），不可再次编辑或提交。
- 实时总额计算，显示于提交按钮上方。
- 基础安装需勾选「我已确认」后方可提交。
- 提交后工单状态 `pending_submit` → `pending_review`，明细写入 `provider_submissions`。

### F04 费用核对工作台（重点）

**功能描述**

服务商提交后，系统自动将每条明细映射到标准费用项并生成核对结果，分为五种状态；operator 仅需处理异常项（金额差异 / 合同已含 / 未识别），确认后生成结算账单。

**五状态核对逻辑**

| 状态 | 含义 | 人工处理 |
| --- | --- | --- |
| 一致（consistent） | 金额与标准完全一致 | 无，自动通过 |
| 合并一致（merged_consistent） | 多条提交聚合成一条标准项 | 无，自动通过 |
| 金额差异（amount_diff） | 单价/数量与标准不符 | 接受差额 / 驳回 |
| 合同已含（contract_included） | 该费用已含在合同基础费内 | 一键确认驳回 |
| 未识别（unrecognized） | 未匹配到标准项 | 手动匹配 / 驳回 |

**用户故事**

- 作为 operator，我希望看到系统自动核对结果，以便只处理异常项。
- 作为 operator，我希望对「合同已含」一键驳回、对「金额差异」接受/驳回、对「未识别」手动匹配标准项。
- 作为 operator，我希望看到差额汇总（+/- 符号），以便快速判断整体差异。

**验收标准**

- 自动通过项与需人工处理项分区展示。
- 五状态以颜色 + 行左侧 4px 色条区分（差异红 / 一致绿）。
- 差额列显示 +/- 符号，正数绿、负数红。
- 「合同已含」由 `standard_fee_items.included_in_base_fee` 驱动自动标记。
- 「确认核对完成」按钮校验：仍存在未处理异常项（status 为 amount_diff / contract_included / unrecognized 且无 manual_note）时置灰不可点击，悬停提示「还有 X 项需要处理」。
- 处理完所有异常项后「确认核对完成」可用，点击触发账单生成。

### F05 结算账单生成与输出

**功能描述**

核对完成后生成结算账单（含费用明细、核减记录、最终应付金额），支持三种输出：页面留存、PDF 导出、复制链接发送；账单生成后锁定服务商提交明细。

**用户故事**

- 作为 operator，我希望生成可追溯的结算账单，以便留存与结算。
- 作为业务侧，我希望通过 PDF 或链接获取账单，以便确认与归档。
- 作为 operator，我希望账单生成后提交明细不可再改，以便保证可追溯性。

**验收标准**

- 账单编号 `SET-XXXX` 唯一；含服务商申报总额、核减金额、最终应付金额。
- 三种输出可用：页面留存、PDF 导出（jsPDF）、复制链接发送。
- 生成后相关 `provider_submissions.is_locked=1`，一个工单最多一张账单。

### F06 数据看板

**功能描述**

可视化展示核对数据：KPI 统计卡、近 6 个月核对金额柱状图、本月服务商金额占比、待处理差异表。

**用户故事**

- 作为 operator/admin，我希望看到核对效率与金额趋势，以便支撑管理决策。
- 作为 operator，我希望直接看到待处理差异清单，以便快速进入核对。

**验收标准**

- 5 张 KPI 卡（本月工单 / 待核对 / 本月核对金额 / 平均核对耗时 / 争议率）。
- 近 6 月金额柱状图（渐变蓝）+ 服务商占比横条 + 待处理差异表。

### F07 标准费用库管理

**功能描述**

admin 维护全局固定的京东标准费用项（新增、编辑、停用），修改留痕并对历史工单生效。

**用户故事**

- 作为 admin，我希望维护标准费用项，以便统一核对基准。
- 作为 admin，我希望停用（而非删除）标准项，以便保留历史留痕。

**验收标准**

- 标准费用项增、改、停用/启用切换。
- 停用用 `is_active=0`（软停用），不物理删除。
- 停用只影响新增核对匹配，不影响历史工单中已生成的 `reconciliation_items` 记录。
- 停用前弹出确认提示：「停用后新工单将无法匹配此项，历史数据不受影响，确认停用？」
- 修改留痕（`updated_at` + 操作人），对历史工单生效。

## 4. 数据流程

```
发起核对 ──> 服务商提交 ──> 系统自动核对 ──> 人工处理 ──> 生成账单 ──> 锁定
   │            │             │              │             │
F01 建工单   F03 填明细    F04 生成五状态   F04 异常项    F05 账单    F05 is_locked=1
 待提交      待核对         待核对          待核对         已核对 → 已结算
```

**工单状态流转**

```
pending_submit ──提交──> pending_review ──核对完成──> reviewed ──结算──> settled
      │                      │
      │                      └──有争议──> disputed
      └──超期未提交（仍为待提交）
```

1. **发起核对**：operator 创建工单（`pending_submit`），生成 `submit_token`。
2. **服务商提交**：服务商经 `/submit/{token}` 填写明细，工单转 `pending_review`。
3. **系统自动核对**：映射标准库生成五状态核对明细。
4. **人工处理**：operator 处理异常项（接受/驳回/手动匹配）。
5. **生成账单**：确认核对完成，生成 `settlement_bills`，工单转 `reviewed`。
6. **锁定**：相关 `provider_submissions` 置 `is_locked=1`；结算后工单转 `settled`。

## 5. 非功能性需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 工单列表页加载 < 2s；核对工作台正常渲染 < 3s |
| 安全 | `submit_token` 唯一且一次性使用场景；服务商提交后明细不可修改（`is_locked`）；admin/operator 需登录鉴权 |
| 兼容 | 支持 Chrome / Safari 最新版（内网桌面端） |
| 可追溯 | 服务商提交、系统核对、人工处理、账单全链路留存，可导出 PDF |
| 数据一致性 | 金额以「分」存储，避免浮点误差；外键约束保证引用完整 |
